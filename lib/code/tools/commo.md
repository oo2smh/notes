# 🐧 Tldr
- **What**: How to communicate *effectively* especially in the context of parsing code
- **Why**: To have the other party be able to understand you
- **How**: Through concise, clear speech/writing and other techniques

## *SUMMARY*
> Communicate well using the CAP 🧢 principle (concise, abstract, precise). These principles are applied to 3 specific speaking scenarios
1. Feynman (teaching)
2. Parsing (reading)
3. Code-along (coding)

# 🔑 Keywords
## *UNIVERSAL PRINCIPLES*
```yaml
CAP: Concise, Abstraction, Precise
Concise : Be Abrupt and to the point
Abstracted: Finetune level of detail
Precise: Use the right words for the job
```

## *ABSTRACTION LEVELS*
```yaml
User Level: The *what*. Intention of writer
Implementation: The *how*. Tools used to accomplish tasks
ELI5: General Logic. No programming concepts.
General Coder: Loops. Conditionals. Etc
Niche-Programmer: Language specific syntax
```

## *FEYNMAN*
> Techniques/strategies to effectively TEACH
```yaml
Associations: Cater to audience's known
  # Analogies: Great way to make the unknown familiar
Examples: Principle targeted examples
WPW: Moving through abstraction layers
-LV1: Concept. Introduce the concept. Definition. Analogy.
-LV2: Important Details
-LV3: Other Details. Usually a concrete example.
```

## *CODE PARSING*
```yaml
Mind Your Words: Precision matters! Distinguish between similar, but diff words (arg vs param)
  # Variables: Declaration, Initialization, Assignment
  # Functions: Definition, Parameters, Invocation
  # STD LIB: Standard library Methods/Properties
DRY: Don't repeat yourself
Emphasis? (LTR vs RTL): Directionality matters! Determine whether to emphasize subject or action
ABCD Framework: Anomalies, Behavior, Concepts, Details
Flat > Nesting: Flat is easier to conceptualize than nesting
  # IF you do nest, refer to levels as outermost, middle, and innermost
```

## *CODE ALONGS*
> Secondary things to keep in mind as you code/explain
```yaml
Vocalize Everything: Don't get silent
Expectations: Explain what you expect code to output
Announce as you do: Explain as you write lines of code
Minimize Negativity: Avoid certain words
```
