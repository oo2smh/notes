# tldr 🐧
- **What**: Toolchain refers to all additional code that is often bundled together with the SDK to run/build the code. 2 most prominent tools include the `pkg manager`, `venv manager`, `test runner`, `bundler`. Some of these must be explicitly downloaded.
  - `pkg manager`: download/update `pkg` (code bundles written for a specific functionality). Dependency management.
  - `venv manager`: isolates a project to its packages to a specific folder by creating a venv that is attached to the directory.
  - `test runners`: allows you to write and run tests
  - `bundler`: packages up many separate files into one/few bundle. Memory savings. Performance gains.
  - `transpiler/minifier`: Transpiler converts old syntax to cutting-edge syntax. Minifiers strips unnecessary chars (whitespace) to reduce the file size.

## *BENEFITS OF MODERN/ALTERNATIVES*
- `Uv`: faster than pip. Can download different py versions. Replaces venv management completely.
- `Pnpm`: saves memory by creating a global store and `symlinking`. If project A & B both use pkg1. Pkg1 is only downloaded once onto the global store and symlinked to both projects. Faster. Huge memory savings.
-`Bun`: multi-tool. pkg manager + runtime. Replaces the pkg manager, test runner, and bundler into one tool.

# Environment Management
> All languages have a concept of isolation. Dependencies/pkgs in one directory is contained to that specific directory. This is done implicitly by default. Python env setup has to be done explicitly! Modern tooling attempts to make it behave more like the other languages.

## Python Default Behavior
- Python was designed to look for pkgs in the global path. To create isolation, requires explicit setup.
- This is done by creating the `.venv` folder.
```md
python -m venv .venv (creates the env)
source .venv/bin/activate  (shell script so that using python points to the current dir not the global)

```


| Default | UV Command | Comments |
| --- | --- | --- |
| python -m venv .venv | uv venv | 1 |
| source .venv/bin/activate | uv run python <script.py> | 2 |
1. Activates the `.venv` folder to allow env isolation
2. `source...` is a shell script that allows python to point to the current dir and not the global directory! Using `uv run python...` avoids this but can be verbose to type each time. Other solutions exists such as `direnv` to auto source upon entry into a python folder.

```bash
# If a .venv exists, use it; otherwise use system python
alias python='[ -d .venv ] && uv run python || python'
```

# Dependency Management
- All package managers lock in the current version of each package into its own file. The lockfile is generated from the config file. You need both files!

| Lang | Pkg Manager | Lockfile | Config File |
|---|---|---|---|
| py | pip | requirements.txt | pip.conf |
| py | uv | uv.lock | pyproject.toml |
| js | npm/pnpm | package-lock.json | package.json |
| js | bun | bun.lockb | package.json |
| go | go mod | go.sum | go.mod |
| java | maven |  pom.xml | pom.xml |

- Even though certain config files might have versions, it is more of a big-picture overview. You cannot list dependencies of dependencies. This is where the `lock-file` comes into play! It lists sub-dependencies, and hashes for all packages.

- Sample Config File
```json
{
  "name": "my-js-project",
  "version": "1.0.0",
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "tsc && vite build"
  },
  "dependencies": {
    "express": "^4.18.2"
  },
  "devDependencies": {
    "typescript": "^5.0.0"
  }
}
```
